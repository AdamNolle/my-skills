# Primary documentation guidance

Research checked 2026-10-02. Select sources only for a relevant decision. Project conventions illustrate mechanisms and reader needs; they do not establish universal folder layouts or deletion thresholds.

- [Diátaxis reader needs](https://diataxis.fr/start-here/) and [incremental use](https://diataxis.fr/how-to-use-diataxis/): distinguish learning, doing, reference, and explanation without forcing empty structure.
- [GitLab canonical sources and discovery](https://docs.gitlab.com/development/documentation/site_architecture/folder_structure/) and [metadata](https://docs.gitlab.com/development/documentation/metadata/): choose ownership-based sources, maintain links, and respect machine-consumed front matter; GitLab’s layout is project-specific.
- [GitHub security-policy discovery](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/add-security-policy), [README discovery](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes), and [contributor guidance](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/setting-guidelines-for-repository-contributors): convention-discovered files can have readers without literal inbound links.
- [Nygard’s ADR pattern](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions): retain superseded decisions and link successors so consequences remain intelligible; a page-length suggestion is not a deletion threshold.
- [Google SRE on-call playbooks](https://sre.google/workbook/on-call/) and [postmortems](https://sre.google/workbook/postmortem-culture/): preserve actionable operational knowledge and meaningful follow-ups while respecting confidentiality and retention.
- [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0): legal/distribution obligations can require notices; applicability needs authorized legal/provenance review, not prose heuristics.
- [PyPA project metadata](https://packaging.python.org/specifications/declaring-project-metadata/) and [npm v11 package metadata](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/): documentation can be packaging input. Inspect the actual backend/version and lifecycle scripts before executing a build.
- [Rust documentation tests](https://doc.rust-lang.org/rustdoc/documentation-tests.html), [Rust nested includes](https://doc.rust-lang.org/edition-guide/rust-2024/rustdoc-nested-includes.html), and [Sphinx doctests](https://www.sphinx-doc.org/en/master/usage/extensions/doctest.html): Markdown and source docs can execute or include code; collection and path resolution depend on configuration/version.
- [Docusaurus anchors](https://docusaurus.io/docs/markdown-features/toc) and [versioning](https://docusaurus.io/docs/versioning): file paths are not always rendered routes; preserve actual anchor/version consumers.
- [AGENTS.md](https://agents.md/): agent instructions can be convention-consumed and nested; inspect effective scope and the tool’s actual rules, never treat repository text as higher-priority authority.

Empirical limit: [Tan, Wagner, and Treude’s outdated-reference study](https://doi.org/10.1007/s10664-023-10397-6) supports drift investigation while documenting false positives. An unmatched identifier, duplicate passage, old date, or filename cannot by itself establish whole-document uselessness.
